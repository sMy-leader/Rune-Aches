## 〇、注释标记约定（先读这一节）

核心文件顶部都有一段"文件名片"：

```
【链路】上游 ──> 本文件 ──> 下游
【职责】这个文件只负责什么
【坑】/【现状】/【扩展】现在哪里是临时方案、以后从哪改
```

行内注释只用四种标记：

| 标记 | 含义 | 读法 |
|---|---|---|
| `// [为什么]` | 设计取舍，面试最常追问的地方 | 想清楚"不这么做会怎样" |
| `// [坑]` | 已知问题或以后容易踩的地方 | 改相关代码前先看 |
| `// [关键]` | 理解这条链路必须知道的点 | 建议背下来 |
| `// [注意]` | 参数含义、边界条件 | 调参时看 |

**建议读法**：先读文件头（30 秒知道它在链路里的位置），再读公开方法，最后扫一遍 `[坑]`。

## 二、分层地图（依赖只能向下）

```
RuneAshes.UI         ← HUD / 三选一 / 结算 / 链编辑器 / 打击感 / 主题与字体
RuneAshes.Gameplay   ← Player / Enemy / Rune / Combat / Progression / Vfx / Camera / Input / Debug
```

```
├── Camera/       TopDownCamera
├── Input/        IInputSource、PlayerInputSource
└── Debug/        DebugChainHud（场景里已禁用）

UI/
├── Common/       UiTheme、UiBootstrap
```

## 四、十一个"为什么"

1. **为什么用 ChainCompiler 而不是运行时直接遍历链？**
   玩家改链是低频操作，施法是高频操作。编译把"校验 + 参数折算"提前，运行时只跑不可变 plan。

2. **为什么效果只依赖 `IRuneWorld`？**
   效果层可以在 EditMode 用 fake world 单测，不需要场景、不需要 Play。

3. **为什么伤害用 struct 而不是 class？**
   热路径每帧可能几十次伤害，class 会持续分配 → GC 尖峰。

4. **为什么有 `depth / ProcBudget / SameFrameGate` 三件套？**
   能耗是静态闸门，管不住动态递归。三者分别管"单链深度""全局频率""同帧重复"。

5. **为什么随机要可播种？**
   种子系统/每日挑战/回放都依赖它；`IRandom` 从第一天就在。

6. **为什么 Data 层 `noEngineReferences = true`？**
   强制数据层不碰 UnityEngine，保证纯 NUnit 可测、可换 Luban、可进热更程序集。

7. **为什么动画状态机分两层（Animator + 代码 FSM）？**
   Animator 只负责"播什么"；"什么时候追、什么时候打"放在 `EnemyBrain`/`PlayerController`。
   这样行为可单测、可对 300 单位降频，将来换 Flow Field 不用重推动画资产。

8. **为什么玩家会打自己？怎么修的？**
   弹丸/范围查询用 `OverlapSphere(~0)`，玩家自己的 `CharacterController` 上挂着 `PlayerHealth`，
   弹丸出生在脚下第一帧就命中自己。`UnityRuneWorld` 缓存 `_owner`，所有命中查询用 `IsOwner` 跳过。

9. **为什么三选一候选要先 `ChainCompiler` 预检？**
   UI 不应该知道槽位/能耗规则。`RunProgression` 用"加入或替换最后一个修饰"的假设先编译，
   只把 `IsValid` 的符文放进候选；玩家看到的每一张卡都一定装得上。

10. **为什么时间层用暂停引用计数 + 独立顿帧层？**
    曾经 HitFeedback 把 `timeScale=0.05`，升级界面把 0.05 存成"暂停前倍率"，选完恢复成 0.05，
    永久慢动作。现在暂停是 `PushPause/PopPause` 深度，顿帧独立计时，有效倍率由 `UnityTime` 一层计算。

11. **为什么 UI 字体要通过 `UiBootstrap` 注入？**
    `UiTheme` 是静态主题；如果每个界面各自找字体，会出现有的界面思源、有的界面系统字体。
    `UiBootstrap` 用 `[DefaultExecutionOrder(-1000)]` 在 UI Awake 前统一设置。

## 八-B、W4b 前架构体检（2026-11-08）

### 结论

当前可以进 W4b，但**不要直接开始加 Boss**。先修三件事：

1. 三选一候选池只出修饰，导致 orbit/效果类卡不可测
2. `EnemyBrain` 的 Kind 分支继续增长，Boss 会把它变成巨型 switch
3. 性能基线、音效、低模杂兵还没有支撑 W4b 的验证

### 解耦优先级

| 优先级 | 动作 | 原因 |
|---|---|---|
| P0 | 扩三选一候选池：触发 / 效果 / 修饰都可出 | orbit 和新构筑才能测 |
| P0 | 抽 `EnemyDefinition`（HP/速度/攻击/动画适配器/权重） | 远程/自爆/精英/Boss 不再靠 switch 硬编码 |
| P1 | 加轻量 `RunContext`/`GameRoot`，注入 `ITableProvider`、`IVfxService`、`WaveSpawner` | 去掉 `RuneCaster.Rebuild` 的 `new TableProvider()` |
| P1 | 把 VFX 调用改成事件/接口，不在 `Projectile` 里直接依赖静态服务 | 方便关闭 VFX、测试和以后换实现 |
| P2 | `WaveSpawner` 改数据驱动波次表 | 精英/Boss 波次不写死在代码 |
| P2 | 攻击去重改 `IDamageable` 实例，不按 Collider | 一敌多碰撞体的正式敌人 |
| P2 | `SameFrameGate` 按 `ChainId` 分开记录 | 多链装配前必须改 |
| P3 | UI 加 `UIRouter`，把 UI 组件从 Player 上移走 | 组合根清晰，场景重载更稳 |

### 玩法创新 / 可玩性 / 爽度

1. **链能耗的“风险/收益”**
   - 满能耗时允许“超载施法”：伤害/频率提高，但短暂降低移速或消耗 HP
   - 让玩家主动做“这一发值不值”的决策，而不是只看数值

2. **符文共鸣**
   - 同类别/同主题组合给套装效果：例如燃烧 + 爆炸 → 火焰连锁
   - 链编辑器显示“共鸣候选”，提高拼装动机

3. **精英词缀要有反制**
   - 护盾：吸收 40% / 护盾值 200；高单发伤害可破盾
   - 突进：红色拖尾 + 加速；冲刺无敌帧可穿
   - 分裂：击杀后分裂；范围伤害可清子体
   - 每个词缀都要有“看懂了就能处理”的窗口

4. **Boss 先做“读招”而不是堆血**
   - 两阶段；技能预警圈/线；阶段转换时清弹或给安全区
   - Troll 降级为 Boss 原型，杂兵另找低模

5. **升级选择要有取舍**
   - 候选池放开触发/效果/修饰；加 reroll/banish（先做 reroll 即可）
   - 卡面显示 DPS/能耗/槽位变化，避免“看不懂就不选”

6. **爽度优先级**
   - 音效 > 新 VFX > 新数值
   - 命中音、击杀音、升级音、Boss 阶段音先补
   - 顿帧/震屏/VFX 已经有基础，下一刀是声音和 Boss 预警

7. **不要现在扩内容**
   - 先把 3 种敌人 + 1 Boss 做透
   - 20 符文里优先让 E1/E2/E3/E4/E5 + M1–M7 都能抽到、能感知差异

### W4b 建议顺序

1. 修三选一候选池（0.5 天）
2. 抽 `EnemyDefinition` + 精英词缀（1~2 天）
3. Boss 两阶段 + 预警（2 天）
4. SFX + 300 敌人/500 弹幕基线（1~2 天）
5. Playtest + kill criteria

**不要**在 W4b 里同时做 Atlas、Boot/Loading、链编辑器拖拽；这些会掩盖核心循环的问题。

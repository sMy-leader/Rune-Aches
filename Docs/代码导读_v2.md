## 〇、注释标记约定（先读这一节）

核心文件顶部都有一段"文件名片"：

```
【链路】上游 ──> 本文件 ──> 下游
【职责】这个文件只负责什么
【坑】/【现状】/【扩展】现在哪里是临时方案、以后从哪改
```

行内注释只用四种标记：

| 标记 | 含义 | 读法 |
|---|---|---|
| `// [为什么]` | 设计取舍，面试最常追问的地方 | 想清楚"不这么做会怎样" |
| `// [坑]` | 已知问题或以后容易踩的地方 | 改相关代码前先看 |
| `// [关键]` | 理解这条链路必须知道的点 | 建议背下来 |
| `// [注意]` | 参数含义、边界条件 | 调参时看 |

**建议读法**：先读文件头（30 秒知道它在链路里的位置），再读公开方法，最后扫一遍 `[坑]`。

## 二、分层地图（依赖只能向下）

```
RuneAshes.UI         ← HUD / 三选一 / 结算 / 打击感 / 主题与字体
RuneAshes.Gameplay   ← Player / Enemy / Rune / Combat / Progression / Camera / Input / Debug
RuneAshes.Framework  ← 时间 / 随机 / 资源 / 存档 / 启动
RuneAshes.Data       ← 配置表 + 数据定义（noEngineReferences = true）
RuneAshes.Editor     ← 配置生成 / 场景构建 / 资产导入与验收 / 动画构建
```

游戏内目录：

```
Gameplay/
├── Player/       PlayerController、PlayerAnimatorDriver、PlayerHealth
├── Enemy/        EnemyActor、EnemyAnimatorDriver、EnemyBrain
├── Rune/         ChainCompiler、RuneCaster、TriggerRouter、Effects/、Factories
├── Combat/       Projectile、IRuneWorld、UnityRuneWorld、ProcBudget...
├── Progression/  ExperienceSystem、RunProgression、RunStats、WaveSpawner
├── Camera/       TopDownCamera
├── Input/        IInputSource、PlayerInputSource
└── Debug/        DebugChainHud（场景里已禁用）

UI/
├── Common/       UiTheme、UiBootstrap
├── Hud/          HudView
├── Progression/  UpgradeScreen
├── Settlement/   SettlementScreen
└── Effects/      HitFeedback、FloatingDamageText
```

为什么要分层：`Gameplay` 将来可整体进热更程序集；`Data` 不依赖引擎，所以能用纯 NUnit 测、也能被 Luban 替换。

## 四、十一个"为什么"

1. **为什么用 ChainCompiler 而不是运行时直接遍历链？**
   玩家改链是低频操作，施法是高频操作。编译把"校验 + 参数折算"提前，运行时只跑不可变 plan。

2. **为什么效果只依赖 `IRuneWorld`？**
   效果层可以在 EditMode 用 fake world 单测，不需要场景、不需要 Play。

3. **为什么伤害用 struct 而不是 class？**
   热路径每帧可能几十次伤害，class 会持续分配 → GC 尖峰。

4. **为什么有 `depth / ProcBudget / SameFrameGate` 三件套？**
   能耗是静态闸门，管不住动态递归。三者分别管"单链深度""全局频率""同帧重复"。

5. **为什么随机要可播种？**
   种子系统/每日挑战/回放都依赖它；`IRandom` 从第一天就在。

6. **为什么 Data 层 `noEngineReferences = true`？**
   强制数据层不碰 UnityEngine，保证纯 NUnit 可测、可换 Luban、可进热更程序集。

7. **为什么动画状态机分两层（Animator + 代码 FSM）？**
   Animator 只负责"播什么"；"什么时候追、什么时候打"放在 `EnemyBrain`/`PlayerController`。
   这样行为可单测、可对 300 单位降频，将来换 Flow Field 不用重推动画资产。

8. **为什么玩家会打自己？怎么修的？**
   弹丸/范围查询用 `OverlapSphere(~0)`，玩家自己的 `CharacterController` 上挂着 `PlayerHealth`，
   弹丸出生在脚下第一帧就命中自己。`UnityRuneWorld` 缓存 `_owner`，所有命中查询用 `IsOwner` 跳过。

9. **为什么三选一候选要先 `ChainCompiler` 预检？**
   UI 不应该知道槽位/能耗规则。`RunProgression` 用"加入或替换最后一个修饰"的假设先编译，
   只把 `IsValid` 的符文放进候选；玩家看到的每一张卡都一定装得上。

10. **为什么时间层用暂停引用计数 + 独立顿帧层？**
    曾经 HitFeedback 把 `timeScale=0.05`，升级界面把 0.05 存成"暂停前倍率"，选完恢复成 0.05，
    永久慢动作。现在暂停是 `PushPause/PopPause` 深度，顿帧独立计时，有效倍率由 `UnityTime` 一层计算。

11. **为什么 UI 字体要通过 `UiBootstrap` 注入？**
    `UiTheme` 是静态主题；如果每个界面各自找字体，会出现有的界面思源、有的界面系统字体。
    `UiBootstrap` 用 `[DefaultExecutionOrder(-1000)]` 在 UI Awake 前统一设置。

- **测试**：EditMode **47** 个用例，MCP `run_tests` 约 1.5 秒跑完。
- **时间**：不要用 `Time.timeScale` 判断暂停；读 `GameTime.Current.EffectiveScale` / `PauseDepth`。
- **Play 验证**：`execute_code` 可直接读：
  - `PlayerHealth.Health / IsAlive`
  - `ExperienceSystem.Level / CurrentXp / XpToNext`
  - `RunStats.Kills / Elapsed`
  - `WaveSpawner.WaveIndex / AliveCount`
  - `RuneCaster.AutoFireEnabled`；私有 `_castCounter` 可反射读取
  - `Animator.GetCurrentAnimatorStateInfo(0/1)`
- **UI 层级**：HUD sort 0、HitFeedback 50、Upgrade 100、Settlement 200。
- **截图**：MCP `manage_camera screenshot` → `Captures/`（已 ignore）。
- **时间守卫**：`TimeArchitectureTests` 会扫描 `Assets/RuneAshes`，除 `UnityTime.cs` 外出现 `Time.timeScale =` 直接失败。
- **动画重建**：菜单 `Rune Ashes/Animation/Build Player Animator`（幂等）。
- **资产验收**：菜单 `Rune Ashes/Assets/Audit Models` → `Docs/资产盘点报告.md`。
- **构建流程**：改代码 → `refresh_unity(compile=request)` → 构建。MCP 构建不会自动先编译。

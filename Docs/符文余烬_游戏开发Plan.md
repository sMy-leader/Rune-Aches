# 《符文余烬》（工作名）游戏开发 Plan

> 3D 俯视 Roguelike 幸存者类 + 符文链式编程武器系统
> 定位：求职作品集 → 持续打磨 → Steam 上架（独游）
> 作者：solo 开发 | 目标岗位：客户端 Gameplay / 系统框架
> 引擎：Unity 6.3 LTS（URP，利用 Render Graph / GPU Resident Drawer 等新特性）
> 版本管理：Git + Git LFS（solo 免费方案，资产量大再考虑 Unity Version Control）
> 创建日期：2026-10-27 | 版本：v1.2

---

## 一、项目定位与目标

### 1.1 一句话概念
你是一名符文师。法术不是学来的，而是**拼出来的**——在枪林弹雨中拾取符文、组装武器链，从森林一路杀回被腐化的城市。

### 1.2 三阶段目标
| 阶段 | 时间 | 目标 | 产出 |
|---|---|---|---|
| 切片期 | 第 1~3 月 | 求职用最小可玩切片 | 可录 demo 视频 + 简历技术点 + 可投递的 build |
| 扩展期 | 第 4~8 月 | 内容量与深度扩展 | Steam 商店页 + 试玩版 |
| 上架期 | 第 9~12 月 | 打磨至可上架品质 | Steam Demo / EA 发布决策 |

### 1.3 求职对接（每个系统都是简历 bullet）
- **Job System + Burst**：同屏 300+ 敌人与弹幕，稳定 60 FPS，附 Profiler 对比数据
- **符文链系统**：数据驱动的运行时行为组合系统（ScriptableObject + 责任链管线），组合爆炸级 build 空间
- **YooAsset + HybridCLR**：完整商业化热更管线（包体分组、版本管理、边玩边下）
- **Behavior Designer**：分层敌人 AI（杂兵/精英/Boss），行为树可视化调试
- **性能优化**：零 GC 热路径、对象池、合批与 LOD，能讲清楚每一次优化前后的数据
- **VContainer + UniTask**：清晰的分层架构与异步流管理，代码经得起面试官翻
- **Flow Field 流场寻路**：数百敌人朝同一目标寻路的品类标志性算法（《They Are Billions》《Midnight Horde》同款），替代 A*，附推导文档
- **空间哈希分桶弹幕碰撞**：自研 Spatial Hash Grid 把 O(n²) 降 O(n)，绕开 PhysX 自写碰撞——国内面试性能题的高频考点
- **Luban 配置管线**：国内商业团队事实标准（腾讯系出身，原生支持 HybridCLR），Excel→强类型代码，替换手写 SO 数值表
- **BD 源码级理解**：行为树用 Behavior Designer 保证效率，同时研读其 Task 执行模型，并输出《BD 执行模型 vs 我的符文管线设计》对比分析文档——这一节比 demo 本身值钱

### 1.4 竞品对标与定位（面试必答"你和 XX 的区别"）

| 竞品 | 它有的 | 它没有而我们有的 |
|---|---|---|
| 魔法工艺 | Noita 式法术编程拼装 | 2D 像素纯地牢；我们是 3D 俯视 + 幸存者节奏，链槽比自由拼装更轻量易上手 |
| 土豆兄弟 | 数值流派构筑深度 | 装备即数值，无武器编程；我们的构筑改变行为模式而非堆数值 |
| 吸血鬼幸存者 | 品类开创、自动攻击 | 无主动瞄准与构筑编程；我们双摇杆 + 链式构筑 |
| 哈迪斯 | meta 叙事标杆 | 动作 Roguelike 非幸存者；我们 meta 解锁服务于构筑广度 |

**定位一句话**：3D 主动瞄准幸存者 × 链式符文编程 = 品类交叉空位。Steam 页面文案与面试话术统一用这句。

## 二、核心玩法设计

### 2.1 操作与视角
- **3D 俯视**，双摇杆操作：WASD 移动 + 鼠标瞄准主动射击
- 1~2 个主动键位（冲刺必做，第二个预留）
- 打击感三件套：顿帧、屏幕震动、击退/受击反馈（PrimeTween 实现）

### 2.2 切片期打磨标准（3 分钟原则）

切片期每一分钟开发都要问："这能在 demo 视频里被看见吗？"看不见的（精细平衡、大量内容）一律后置。

| 维度 | 切片期达标线 | 明确不做 |
|---|---|---|
| 核心乐趣 | 玩家第 1 次升级三选一就理解"符文能拼"，第 3 次开始期待"再来个分裂我就胡了" | 需要读教程才懂的机制 |
| 构筑差异 | ≥3 种玩法本质不同的构筑：站桩弹幕流 / 冲刺地雷流 / 环绕走位流 | 换皮数值符文（只是换个颜色的伤害数字） |
| 手感 | 开火/命中/击杀三条反馈链完整（顿帧+震屏+音效+飘字），Boss 战有高潮时刻 | 动画细节、皮肤、局外装饰 |
| 平衡 | 没有"明显唯一最优解"，允许胡牌 | 精细数值平衡（上架期的事） |

### 2.3 核心循环
```
选择角色/初始符文 → 进入竞技场（15分钟一局）
  → 击杀敌人掉落经验与符文
  → 升级：三选一（新符文 / 强化链上槽位 / 属性）
  → 组装与调整武器链 ← 核心乐趣
  → 波次推进：杂兵潮 → 精英 → Boss
  → 结算：存活时间 / 击杀数 / 掉落符文币
  → meta 解锁：新符文、新槽位、新角色
  → 带着新构筑可能性开下一局
```

### 2.4 符文链系统（核心创新）

**结构**：一条链 = 1 个触发器槽 + 1 个效果槽 + N 个修饰槽（N 随 meta 解锁成长）

```
[触发器] → [效果] → [修饰1] → [修饰2] → [修饰3]
```

**示例构筑**：`[击杀触发] → [直射弹] → [分裂x3] → [弹射2次] → [附加燃烧]`
= 一把"击杀引发链式燃烧弹"的武器

**符文库规划（切片期 20 个，最终 60+）**

> 20 个符文的详细数值、能耗、连锁设计见配套文档《符文系统设计_v1.md》

| 类型 | 切片期 | 扩展示例 |
|---|---|---|
| 触发器（6） | 定时、击杀、命中、冲刺后、受伤、常驻光环 | 连击数触发、低血量触发、暴击触发 |
| 效果（7） | 直射弹、散射、环绕球、地雷、冲刺斩、光束、召唤物 | 黑洞引力、闪电链、领域地面 |
| 修饰（7） | 分裂、弹射、穿透、燃烧、冰冻、爆炸、追踪 | 吸血、连锁增幅、延时引爆 |

**关键设计原则**
- 每个符文 = 一个 ScriptableObject，效果与修饰均为**可复用原语**
- 运行时按链序执行（责任链/管线模式），修饰器以 Decorator 模式包裹效果
- **架构上为"自由节点图"留门**：触发/逻辑/效果三分的接口设计，后期若升级为自由连线模式（老玩家深度内容），原语层不重写

**平衡安全网**：每个修饰器附带"能量消耗"值，链的总能耗有上限——用数值闸门控制组合爆炸，而不是禁止组合。

**决策分层（心流保护，本设计最重要的 UX 决策）**

符文链是"高决策"系统，幸存者类是"低决策"爽游，天然矛盾，靠拆解决策时机化解：
- **战斗中**：升级三选一只有"拿哪个符文"一个决定，3 秒内可选完，不打断心流
- **喘息窗口**（波次间隙/Boss 前）：才打开链编辑界面组装调整
- **一键推荐组装**兜底：休闲玩家全程可只用推荐，硬核玩家在喘息窗口手动细调——一个系统，两种消化速度

**质变原则（构筑的灵魂）**
- 判断修饰器好坏的唯一标准：**是否改变玩家的操作行为**。`弹射`→玩家主动站进怪群 ✅；`伤害+20%`→行为不变 ❌
- 连锁反应设计：每加一个符文先问"它与现有符文的最强连锁是什么"。示例：`击杀触发+爆炸` = 杀一个炸一片、炸死的再触发爆炸——玩家追求的"这把胡了"就是这种瞬间
- 符文库配比目标：质变型 ≥ 60%，数值填充型 ≤ 40%

### 2.5 敌人设计与敌我咬合（切片期）
| 层级 | 数量 | 设计 |
|---|---|---|
| 杂兵 | 3 种 | 近战冲撞 / 远程弹幕 / 自爆，BD 行为树实现 |
| 精英 | 1 种 | 带词缀（护盾/分裂/加速），掉落高级符文 |
| Boss | 1 种 | 森林守护者，两阶段，Timeline 出场演出 |

**敌我咬合（counterplay）**：敌人是构筑的"考题"，否则构筑只剩数值比拼。
- 护盾怪：高频低伤刮痧 → 利好单发高伤构筑
- 虫群：数量压制 → 利好 AOE/弹射，克制单体
- 极速突进怪：难以风筝 → 利好冰冻/减速修饰
- 精英"反构筑词缀"：如"远程反弹"强迫弹幕流换近战构筑打它——玩家调链的行为有了战斗层面的理由

### 2.6 节奏曲线（15 分钟一局的呼吸感）

```
0~3 分钟  脆弱期：教学 + 第一块符文，生存压力低
3~10 分钟 成型期：构筑逐渐闭合，连锁开始出现
10~13 分钟 压力峰值：精英潮，检验构筑
13~15 分钟 Boss 高潮：演出 + 碾压或惜败
```

- 压力峰值与**喘息窗口**交替出现，喘息窗口即链编辑时机（与决策分层咬合）
- 铁律：任何时刻连续 3 分钟内必须有一次正反馈（新符文/新连锁/清屏爽感）

### 2.7 meta 局外成长（哈迪斯式解锁制）
- **符文图鉴**：局内掉落的符文币解锁新符文进入卡池
- **槽位成长**：初始链 3 槽 → 解锁至 5 槽
- **角色**：切片期 1 个（标准符文师），扩展期加 2 个（不同初始链与天赋）
- 存档：MessagePack 序列化（图鉴/货币/槽位/设置），run 中断存档用 Newtonsoft JSON 方便调试

### 2.8 世界结构（复用现有资产）
| 生物群系 | 资产来源 | 解锁阶段 |
|---|---|---|
| 腐化森林 | 现有森林资产 | 切片期 |
| 废弃村庄 | 现有村庄资产 | 扩展期 |
| 城市废墟 | 现有城市资产 | 上架期 |

地图做法：中小型竞技场，用围栏/迷雾/毒圈收拢边界，**不做开放世界**。每局内用波次推进，Boss 战后进入下一群系（一局穿越 1~3 个场景，视阶段而定）。

### 2.9 玩法演进路线（上架期及以后，按优先级）

| 优先级 | 功能 | 价值 |
|---|---|---|
| 1 | **构筑码分享系统**：武器链导出为分享码（MessagePack 序列化 + Base64），他人粘贴直接复现构筑 | 留存 + 社区自传播 + 简历亮点三合一；玩家为"抄大佬构筑"回流，视频作者为展示构筑传播 |
| 2 | **种子系统 / 每日挑战**：确定性随机，同种子全服同图同掉落 | 排行榜与竞速的地基；展示随机数治理能力 |
| 3 | **自由节点图模式**：插槽链升维成自由连线 | 老玩家深度内容；架构期接口已留门，兑现成本低 |
| 4 | **每周 Mutator 词缀**：全局规则修改（如"本周爆炸范围翻倍但玩家也吃伤害"） | 低成本持续更新，维持 EA 阶段更新频率 |
| 5 | **NGO 合作模式**：双人链可互相"接线"（我的触发器接你的效果） | 联机独有的玩法创新，而非单纯多人打怪 |

**演进总原则**：切片期卖"创新的广度"（一个没见过的机制），上架期卖"系统的深度"（这个机制能挖多久）。架构期留的所有门（节点图/NGO/Luban 热更）全部为此服务。

## 三、技术架构

### 3.1 分层架构
```
┌─ 表现层  PrimeTween 动效 / URP 后处理 / Timeline 演出 / VFX
├─ 玩法层  符文链管线 / 玩家控制器 / 波次管理 / meta 系统
├─ 战斗核心  Job System + Burst / Flow Field 寻路 / 空间哈希弹幕碰撞 / 对象池
├─ AI 层   Behavior Designer 行为树
├─ 渲染层  URP Render Graph / GPU Resident Drawer（万人同屏渲染）
├─ 框架层  VContainer DI / UniTask 异步 / 事件总线 / 状态机
├─ 数据层  Luban 配置管线（Excel→强类型代码）/ MessagePack 存档
└─ 基础层  YooAsset 资源 / HybridCLR 热更
```

### 3.2 关键架构决策
1. **符文执行器数据驱动**：所有效果是数据 + 原语组合，禁止为单个符文写硬编码逻辑
2. **热路径零 GC**：敌人、弹幕、飘字全部对象池；伤害数字用合批 UI 或 TextMesh 池
3. **Job System 边界**：敌人移动/碰撞进 Job，游戏逻辑回主线程消费结果——用数据（NativeArray）而非引用通信
4. **为 NGO 预留接口（不实现）**：
   - 输入层抽象（ICommand 模式），本地输入与网络输入同接口
   - 战斗核心不直接依赖场景对象引用，走 ID 寻址
   - 伤害结算集中在服务端可移植的纯函数模块
   - 原则：**接口预留，实现后置**，不为联机提前支付开发成本
5. **热更粒度**：玩法逻辑程序集与框架程序集拆分，符文本体是数据资产（可热更），公共原语在框架层
6. **寻路选型**：敌人寻路不用 NavMesh/A*，用 **Flow Field**（整个竞技场一张场，几百单位共享一次计算，O(1) 查询）。幸存者品类同目标寻路的最优解，《Vampire Survivors》其实只是"朝玩家转向+简单避障"，我们做得更硬核
7. **弹幕碰撞自研**：不走 PhysX（Collider 开销大且不可控），自研**空间哈希网格**做粗筛 + 精确检测，全程 Job 化。弹幕墙、命中特效互不阻塞
8. **对象池**：用 Unity 官方 `UnityEngine.Pool`（不重复造轮子），池化对象约定 Reset 契约，防"池污染" bug
9. **数值配置走 Luban**：符文数值、敌人属性、波次表全部 Excel 配置 → Luban 生成强类型代码 + bytes 资源，支持热更。**禁止**把数值写死在 SO 里——这是商业团队和业余项目的分水岭
10. **渲染优化**：同屏大量敌人启用 Unity 6 的 GPU Resident Drawer（GPU 驱动渲染）+ SRP Batcher，Render Graph 管理自定义 Pass（描边/扭曲等符文特效）

### 3.3 性能目标（简历可量化）
- 同屏 300 敌人 + 500 弹幕：60 FPS（目标机器：主流游戏本）
- 热路径 GC.Alloc = 0 / 帧
- 切图加载 < 2s，YooAsset 边玩边下无卡顿

### 3.4 新增技术学习清单（现有栈之外，按求职 ROI 排序）

| 排序 | 新技术 | 学什么 | 理由 |
|---|---|---|---|
| 1 | **空间哈希 + 零GC池化** | 自研碰撞粗筛、UnityEngine.Pool 契约设计 | 成本极低收益极高，国内性能面试最高频考点 |
| 2 | **Flow Field + Job System** | cost/integration/direction 三场生成、Burst 化 | 已有 Job 基础，构成 demo 最强技术卖点 |
| 3 | **Luban 配置管线** | Excel 表结构定义、代码生成、热更联动 | 国内商业事实标准，进厂即用的工业流程 |
| 4 | **GPU Resident Drawer / Render Graph** | Unity 6 渲染新管线、自定义 Pass | 新引擎特性的实战经验，同龄人简历上几乎没有 |
| 5 | **Steamworks.NET 全流程** | 成就/云存档/Demo 发布/Next Fest | "上架过 Steam"是简历质变项 |
| 6 | FMOD（可选） | 音频事件、参数化音频 | 补齐音频中间件认知，中型团队加分 |
| 7 | UI Toolkit（可选了解） | 编辑器工具开发可用 | 运行时 UI 仍用 uGUI 主流，了解即可 |

**明确不学的**：DOTS/ECS 全套重写（ROI 低，成功幸存者独游多为 GameObject+池+自写碰撞，了解概念能聊即可）、Wwise 深度（独游阶段用不上）

## 五、AI 辅助工作流

| 角色 | 工具 | 用法 |
|---|---|---|
| 编程助手 | Trae Agent + Unity MCP | 代码生成/重构；场景物体摆放、组件挂载等编辑器操作交给 MCP，口头描述即可 |
| 学习导师 | Trae Agent | 新知识点先让 AI 讲原理+对比方案+出手敲练习题，**不直接抄代码**，每个系统做完能独立讲出 why |
| 美术生成 | 腾讯混元 / Tripo | 角色、敌人模型生成三视图→建模；图标、符文贴图 |
| 音频 | 素材站 → Phase 3 起 FMOD | 切片期用现成音效包，扩展期迁移到 FMOD 做事件化音频管理 |
| 策划辅助 | Trae Agent | 前期做数值预算表（敌人血量/DPS/经验曲线），测试期带数据回来迭代提需求 |

**纪律**：
- 架构决策自己做，AI 生成的代码必须过 review（这是面试时"你真懂吗"的底气）
- 关键系统（符文管线、Job 化战斗）第一版手写，后续迭代才用 AI 加速

## 六、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 手感打磨无底洞 | 高 | Phase 2 设 2 周时间盒，参考游戏逐帧拆解，到点收工 |
| 符文链决策过载吓退休闲玩家 | 高 | 决策分层 + 一键推荐组装兜底，Phase 1 真人试玩专门验证"理解成本"（让完全不知情者 5 分钟内完成首次拼链） |
| 组合爆炸导致平衡崩坏 | 高 | 能耗闸门 + Phase 1 就找真人试玩，数值预算表先行 |
| 范围蔓延（想做更多） | 高 | 切片期功能冻结清单，新想法进 backlog 不进当前版本 |
| AI 代码质量债 | 中 | 每个 PR 自问"能不能给面试官讲清楚这段"，讲不清就重写 |
| 美术资产风格不统一 | 中 | 风格化资产 + 统一后处理调色（LUT），用调色掩盖来源差异 |
| 学业与实习挤压时间 | 中 | 每周固定可执行的最低迭代量（如 2 个符文 + 1 个敌人），保节奏不保量 |

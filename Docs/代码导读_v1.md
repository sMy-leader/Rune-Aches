## 二、分层地图（依赖只能向下）

```
RuneAshes.UI         ← 目前只有占位，W3 接三选一
RuneAshes.Gameplay   ← 玩家/相机/输入/符文链/战斗
RuneAshes.Framework  ← 随机/时间/资源/存档/启动
RuneAshes.Data       ← 配置表 + 数据定义（noEngineReferences = true）
RuneAshes.Editor     ← 生成器/场景构建/构建菜单（不参与运行时）
```

为什么要分层：将来接 HybridCLR 时，`Gameplay` 可以整体进热更程序集；`Data` 不依赖引擎，所以能用纯 NUnit 测、也能被 Luban 替换。

## 四、六个"为什么"（面试最容易被追问的）

1. **为什么用 ChainCompiler 而不是运行时直接遍历链？**
   玩家改链是低频操作，施法是高频操作。编译把"校验 + 参数折算"提前，运行时只跑不可变 plan，避免每帧查表与 GC。

2. **为什么效果只依赖 `IRuneWorld`？**
   这样效果层可以在 EditMode 用 fake world 单测，不需要场景、不需要 Play。测试跑 0.2 秒，而不是等 30 秒进 Play。

3. **为什么伤害用 struct 而不是 class？**
   热路径每帧可能几十次伤害，class 会持续分配 → GC 尖峰。struct + 预分配缓冲是幸存者类的底线。

4. **为什么有 `depth / ProcBudget / SameFrameGate` 三件套？**
   能耗是静态闸门，管不住动态递归。`击杀→爆炸→再击杀` 如果不限，一帧能递归上千次。三个闸门分别管"单链深度""全局频率""同帧重复"。

5. **为什么随机要可播种？**
   Plan 里种子系统/每日挑战排第 2。如果现在用 `UnityEngine.Random`，将来所有掉落/刷怪/词缀都要重写。`IRandom` 从第一天就是可播种的。

6. **为什么 Data 层 `noEngineReferences = true`？**
   强制数据层不碰 UnityEngine，保证它能被纯 NUnit 测、能整体替换成 Luban、也能进热更程序集而没有引擎依赖。

## 六、调试技巧

- **测试**：EditMode 43 个用例，MCP `run_tests` 0.2 秒跑完。改数据/编译器/效果后先跑它。
- **Play 验证**：`execute_code` 可以直接调 `RuneCaster.Cast(direction)`、读 `EnemyDummy.Health`，不用手动操作。
- **读错误**：`read_console` 只看 `error`，比在编辑器里翻 Console 快。
- **场景重建**：`Rune Ashes/Scenes/Build Blockout Arena` 是幂等的，随时可以重来。
- **注意**：MCP 构建不会自动先编译。流程固定为：改代码 → `refresh_unity` → 构建。

## 七、W3 的"完成定义"（可玩 3 分钟）

这一轮不是"加更多符文"，而是把循环闭合。验收标准：

1. 打开 `Arena_Blockout` 点 Play，**连续玩 3 分钟不报错**。
2. **3 种敌人**出现且行为可区分：近战追、远程射、自爆炸。
3. **击杀掉经验**，经验满**弹三选一**，选完链立刻变化并在 HUD 上可见。
4. **玩家有 HP**，会被打死；死亡显示结算（存活时间 / 击杀数）。
5. **至少两条构筑**（如"弹射燃烧"vs"分裂爆炸"）手感明显不同。
6. 43+ 测试全绿，构建成功，60fps（灰盒下）。

不在这轮范围：Flow Field、精英、Boss、音效、正式美术、三选一以外的 meta。

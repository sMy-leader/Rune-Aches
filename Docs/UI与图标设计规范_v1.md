# 《符文余烬》UI 与图标设计规范 v1

> 配套：[美术风格与资源清单_v1.md]（第 3.1-F 节）、[符文语义规范_v1.md]、
> [UI资产清单_v1.md]（全部 UI 清单 + 可直接复制的 Holopix 提示词）
> 用途：统一 UI/图标风格 → 直接用于 AI 生成、界面实现、外包沟通
> 版本：v1.0 | 日期：2026-10-28

## 零、先看结论

| 项目 | 结论 |
|---|---|
| **UI 风格名** | **焦石刻符（Ember-Etched Slate）** |
| 一句话 | "UI 是一块被余烬照亮的黑石板：信息是刻上去的，只有可交互、可拾取和危险会发光。" |
| 与场景的关系 | 场景是"手绘低模 + 暗调环境"；UI 是"黑石/焦木/青铜 + 青绿与琥珀刻痕"，同一套材质语言 |
| 符文图标 | 符号优先（glyph-first），不是小插画；透明底、中心构图、深色描边、单色发光 |
| 链编辑器 | 横向 4 槽，形状 + 颜色 + 文字三重编码；能量流从触发流向效果 |
| 技术方案 | **uGUI + 代码生成**（推荐）；UI Toolkit 作为备选，见第五节 |
| 明确不用 | 玻璃拟态、大面积模糊、霓虹多色描边、大圆角卡片、拟物皮革/羊皮纸 |

**三条铁律**

1. **信息优先于装饰**：任何纹理、光效、动画都不能降低"这是什么、能不能点、为什么不能用"的清晰度。
2. **三重编码**：类别不能只靠颜色区分，必须同时有形状、图标、文字。色盲玩家也要能拼链。
3. **只有"可交互 / 可拾取 / 危险"发光**：UI 底板一律压暗，发光是稀缺资源。

## 一、设计语言

### 1.1 材质与形状

| 元素 | 做法 | 禁止 |
|---|---|---|
| 面板底 | 黑石 `#141A1B`，85~92% 不透明；顶部 1px 冷灰高光 | 玻璃模糊、渐变玻璃 |
| 面板边 | 1px `#2E3B39`；重要面板再加 1px 外侧 `#0B0E0F` | 2px 以上亮色描边 |
| 分隔线 | 1px 刻痕：上暗下亮，模拟凹槽 | 纯白 1px 线 |
| 圆角 | 4~6px；槽位可用 8px | 16px 以上大圆角 |
| 按钮 | 黑石底 + 青铜边；悬停时边缘亮起，不改变底色 | 整块高亮、彩虹渐变 |
| 图标底板 | 无底板，透明；由槽位/卡牌负责底色 | 每个图标自带圆形底 |
| 字体 | 中文思源黑体 SC；英文标题 Cinzel；数字等宽 | 艺术字、描边字、投影字 |

### 1.2 色板（唯一来源：`UiTheme.cs`）

| Token | Hex | 用途 |
|---|---|---|
| `BgVoid` | `#0B0E0F` | 全屏遮罩、最底层 |
| `BgSlate` | `#141A1B` | 面板底 |
| `BgSlate2` | `#1C2425` | 悬停、次级面板 |
| `Line` | `#2E3B39` | 常规边线 |
| `LineStrong` | `#4A5A56` | 选中、焦点 |
| `Text` | `#DCE6E2` | 正文 |
| `TextDim` | `#8C9C97` | 次要信息、禁用 |
| `Amber` | `#E8A13C` | 触发器、能量、强调 |
| `Cyan` | `#45D9C4` | 效果、玩家、可拾取 |
| `Silver` | `#C9D4D0` | 修饰 |
| `Danger` | `#D95C4F` | 错误、敌人弹幕、低血量 |
| `Rare` | `#C9A24A` | 稀有度、升级 |

> 与场景色彩脚本一致：UI 强调 = 琥珀 35°；玩家/可拾取 = 青绿 160~180°；危险 = 红 0~15°。
> 语义色只用于语义，不做装饰色。修饰类用银白，是为了让"琥珀/青绿"保持稀缺。

### 1.3 字体与字号

| 层级 | 字体 | 字号（1080p） | 备注 |
|---|---|---|---|
| 大标题 | Cinzel / 思源黑体 Bold | 40 | 仅主菜单、结算 |
| 面板标题 | 思源黑体 Medium | 28 | 链编辑器、三选一 |
| 正文 | 思源黑体 Regular | 16 | 描述、提示 |
| 次要 | 思源黑体 Regular | 14 | 标签、角标 |
| 数字 | JetBrains Mono / 等宽 | 20~28 | 伤害、DPS、计时 |

**授权**：思源黑体（SIL OFL）、Cinzel（SIL OFL）、JetBrains Mono（SIL OFL），均可商用。
**Steam Deck**：800p 下整体 UI 缩放 0.8，正文不小于 14；所有文字必须可换行，不写死宽度。

### 1.4 间距与栅格

- 基准单位 8px；所有间距取 8 的倍数（8/16/24/32/48）。
- 1920×1080 设计基准；面板最大 1600×900，居中，四周留 160/90。
- 链编辑器槽位 160×200；槽间距 56（中间留给连接线与箭头）。
- 符文库图标 96×96；卡牌图标 160×160；结算构筑图标 64×64。

## 二、符文图标规范（最重要的一套）

### 2.1 三类形状语言

| 类别 | 外轮廓 | 符号母题 | 颜色 | 例子 |
|---|---|---|---|---|
| **Trigger 触发** | 圆 / 六边形 | 时间、眼睛、回响、残影、心、环 | 琥珀 `#E8A13C` | T1 时钟、T2 骷髅回响、T3 连锁箭头、T4 冲刺残影、T5 破碎心脏、T6 光环 |
| **Effect 效果** | 菱形 / 方向性 | 弹道、形态、范围 | 青绿 `#45D9C4` | E1 单箭、E2 扇形三箭、E3 环绕双球、E4 地雷、E5 刀锋、E6 光束、E7 哨戒图腾 |
| **Modifier 修饰** | 圆角方 / 裂片 | 叠加、分叉、穿透、元素 | 银白 `#C9D4D0` | M1 三叉分裂、M2 折射、M3 穿透箭头、M4 火焰、M5 冰晶、M6 爆炸、M7 追踪之眼 |

> 形状优先级高于颜色：黑白剪影下，六边形=触发、菱形=效果、方/裂片=修饰。

### 2.2 构图与图层

```
画布 512×512 → 导出 256×256（2x 下采样）
安全区 8%（约 41px）
主体占 70%，中心构图
图层顺序：
  1. 外发光（6~8px，类别色，30~40% 不透明）
  2. 深色外描边（2px，导出后 1px，#0B0E0F）
  3. 主体石面（深灰 #232B2A，带轻微手绘笔触）
  4. 刻痕凹槽（比石面暗 15%，1~2px）
  5. 刻痕内发光（类别色，核心最亮）
  6. 45° 单侧高光（白 20%，只在上缘）
```

### 2.3 灰度与可读性测试

- 转灰度后，**主体与刻痕明度差 ≥ 40%**。
- 缩到 64×64 仍能认出符号；缩到 32×32 只要求能区分三类形状。
- 20 个图标放在同一张灰度图上，不能有两个"看起来一样"。
- 图标内不出现文字、数字、字母（T1/E1 由 UI 文字负责）。

### 2.4 文件名

严格对应数据表 ID：

```
Assets/Art/UI/RuneIcons/UI_RuneIcon_T1.png
...
UI_RuneIcon_T6.png / UI_RuneIcon_E1.png ... E7 / UI_RuneIcon_M1.png ... M7
```

### 2.5 AI 生成 Prompt（图标专用）

```
game icon of {概念}, a glowing {琥珀/青绿/银白} rune carved into dark slate,
{symbol}, thick dark outline, high contrast, centered composition,
45 degree rim light, transparent background, 512x512,
stylized hand-painted, low-poly flat shading, no text, no letters, no numbers
```

负面：

```
photorealistic, pbr, 8k, blurry, noisy, gradient background, circle badge,
multiple icons, text, letters, numbers, watermark, lens flare
```

概念对照：直接使用 2.1 表中的符号母题，不要临场发挥。

### 2.6 后处理清单（生成后必做）

1. 统一裁切到 512×512，主体居中，安全区 8%。
2. 去掉生成图自带的背景/圆底/文字。
3. 统一外描边 2px，颜色 `#0B0E0F`。
4. 统一外发光（类别色，6~8px）。
5. 导出 256×256 PNG，sRGB，Alpha Is Transparency 开启，Mipmap 关。
6. 灰度测试 + 32px 缩略测试。
7. 登记到 `Docs/资产台账.md`（来源、授权、生成日期）。

### 2.7 没有 AI key 时的占位方案

先用程序化图标：深色圆角方底 + 类别色几何符号（时钟/箭头/三叉等用 SVG/Unity 图形绘制）。
占位图标必须遵守同一套色板与形状语言，保证 UI 能先跑通；正式图标后续替换，不改布局。

### 3.2 尺寸

| 元素 | 尺寸 |
|---|---|
| 面板 | 1600×900，居中 |
| 槽位 | 160×200，间距 56 |
| 槽内图标 | 96×96，距顶 24 |
| 槽内名称 | 16px，单行省略 |
| 能耗角标 | 右下，14px，琥珀 |
| 连接线 | 2px，箭头 12px |
| 能耗条 | 高 10px，10 段，段间距 4 |
| 符文库图标 | 96×96，间距 16 |
| 预览区 | 高 56，位于能耗条下方 |

### 3.3 交互

| 操作 | 鼠标/键盘 | 手柄 |
|---|---|---|
| 选中符文 | 点击库中图标 | 方向键移动焦点 |
| 放入槽位 | 拖拽到槽位，或选中后点击空槽 | A 放入第一个合法空槽 |
| 移除 | 右键槽位，或选中后按 Delete | B / X |
| 替换 | 拖到已占用槽位 | A 替换 |
| 切换分类 | 点击 Tab | LB / RB |
| 查看详情 | 悬停 0.4s | 焦点停留 0.6s |
| 关闭 | Esc / ✕ | Start / B |

**放置规则**

- Trigger 只能进第 1 槽，Effect 只能进第 2 槽，Modifier 只能进第 3~4 槽。
- 拖拽时合法槽位显示类别色边框；非法槽位显示红色斜线，并给出文字原因。
- 同类修饰不允许重复；重复时槽位抖动并提示"每个修饰只能装一次"。

### 3.4 状态

| 状态 | 视觉 |
|---|---|
| 空槽 | 虚线刻痕 + 类别水印 + "空" |
| 已占用 | 实线类别色边框 + 图标 + 名称 + 能耗 |
| 悬停 | 外发光 + 上浮 2px |
| 焦点（手柄） | 2px 亮边 + 四角刻度，不依赖颜色 |
| 拖拽中 | 原件 50% 透明，跟随光标；目标槽高亮 |
| 非法 | 红色边框 + 0.2s 水平抖动 + 顶部错误条 |
| 已满级 | 图标 40% 灰 + 右上角 "MAX" |

### 3.5 动效（PrimeTween，全部 ≤0.3s）

- 放置：缩放 1.0 → 1.08 → 1.0，0.12s。
- 移除：淡出 + 下沉 8px，0.1s。
- 连接线能量流：光点从 Trigger 流向 Effect，2s loop。
- 错误：水平抖动 3 次，0.2s。
- 面板打开：淡入 + 上移 8px，0.15s。
- 升级/确认：金色环扩散，0.3s。

> 动效只用来表达"状态变化"，不做常驻花哨动画；链编辑器打开时游戏应暂停。

### 3.6 预览面板（决定玩家能不能理解构筑）

必须显示四项，且全部来自 `CompiledChain` / 模拟计算，不能写死：

1. **DPS**：单次伤害 × 命中数 × 触发频率的估算值，标注"估算"。
2. **射速 / 触发频率**：T1 显示 interval；T2/T3 显示"每次击杀/命中"。
3. **弹数 / 覆盖**：例如"5 发 × 分裂 3 = 15"。
4. **关键词**：连锁、范围、持续、单体、破盾（来自 Tags）。

> 预览数字允许不精确，但必须随链变化立即更新；玩家靠它理解"加一个修饰到底改了什么"。

## 四、HUD / 三选一 / 结算

### 4.1 HUD（信息优先级：HP > 冲刺冷却 > 经验 > 链缩略）

```
左上：HP 条 280×18 + 数字 100/100
左下：经验条 400×8 + 等级 Lv.7
顶部中央：计时 12:34   波次 8
右下：链缩略（4 个 48×48 图标 + 能耗 7/10）
右上：暂停 / 设置
```

- HP 条不发光；低于 30% 时红色脉冲 + 屏幕四角暗角，不遮挡弹幕。
- 冲刺冷却用 HP 条下方一条 4px 细线，不单独占空间。
- HUD 底板：`BgVoid` 78% 不透明 + 1px `Line`，不用纹理。
- 所有 HUD 元素避开屏幕中心 60% 区域（弹幕区）。

### 4.2 三选一卡牌

| 项 | 规格 |
|---|---|
| 卡牌 | 320×440，间距 32 |
| 图标 | 160×160，占卡面 60% |
| 结构 | 类别色顶边 4px → 图标 → 名称 24px → 描述 14px（最多 3 行）→ 能耗/稀有度 |
| 悬停 | 上浮 8px + 类别色外发光 |
| 选中 | 缩放 1.05 + 金色环 + 0.15s |
| 键盘/手柄 | 左右选择，A 确认，不能取消（必须选一张） |

### 4.3 结算

- 从上到下：存活时间（40px）→ 击杀 / 等级 / 最高连杀 → 构筑链（4 个 64px 图标横排）→ 解锁/货币 → "再来一局"。
- 构筑链是传播点：后续生成 1200×630 分享图时直接复用这套图标与连接线。
- 失败与胜利用同一布局，只换标题颜色与文案，降低实现成本。

## 五、技术实现：uGUI vs UI Toolkit

### 5.1 对比

| 维度 | uGUI（推荐） | UI Toolkit |
|---|---|---|
| 游戏内 HUD | 成熟 | 可用，但生态较新 |
| 手柄导航 | `Navigation` 内置 | 需自己实现焦点环 |
| 拖拽 | `IDragHandler` 成熟 | 需自己处理 Pointer 事件 |
| 动画 | PrimeTween 直接支持 RectTransform/Image | USS transition 为主 |
| 复杂布局 | 需要写布局代码 | USS 更接近 CSS，链编辑器更舒服 |
| 我的自检能力 | 看不到画面，需要你截图 | MCP `render_ui` 可自截图 |
| 与现有工程 | `RuneAshes.UI` 已引用 `UnityEngine.UI` | 需新增 UI Toolkit 依赖与 PanelSettings |
| 面试叙事 | 主流、资料多 | 展示"会新工具"，但风险高 |

**推荐：uGUI + 代码生成。** 理由：手柄/拖拽/动画生态成熟，和 PrimeTween 直接配合，现有 asmdef 已就绪。
**备选：UI Toolkit 只做链编辑器**（复杂布局收益最大），HUD/三选一仍用 uGUI。两套体系会增加主题同步成本，不作为首选。

### 5.2 目录

```
Assets/RuneAshes/UI/
├── Theme/            UiTheme.cs          颜色/字号/间距常量（唯一来源）
├── Common/           UiFactory.cs        面板/按钮/图标/槽位的创建函数
├── ChainEditor/      ChainEditorView.cs  链编辑器主视图
│                     RuneSlotView.cs     单个槽位
│                     RuneLibraryView.cs  符文库
├── Cards/            UpgradeScreen.cs    三选一
│                     UpgradeCardView.cs
├── Hud/              HudView.cs
├── Settlement/       SettlementView.cs
└── Editor/           UiPrefabBuilder.cs  菜单：Rune Ashes/UI/Build All
```

### 5.3 实现约定

1. **主题单一来源**：所有颜色/字号/间距从 `UiTheme` 取，Prefab 里禁止手填 hex。
2. **代码生成**：`UiPrefabBuilder` 生成 Canvas/Prefab，和 `ArenaBlockoutBuilder` 同模式；改布局改代码，不靠手工拖。
3. **数据绑定单向**：UI 只读 `CompiledChain` / `RuneTable`；提交时调用 `RuneCaster.Configure`，不直接改玩法对象。
4. **不阻塞玩法**：链编辑器打开时暂停（`ITime.IsPaused`），关闭时恢复。
5. **可访问性**：焦点环不依赖颜色；文字对比度 ≥ 4.5:1；震屏/伤害数字开关从 `SettingsSave` 读取。

### 5.4 验收方式

每个界面生成两张截图：

- 1920×1080（桌面）
- 1280×720（Steam Deck 近似）

检查：文字不溢出、不重叠；焦点可见；错误态有文字说明；灰度下类别仍可区分。

> 我看不到 Game View，所以截图验收这一步必须由你完成。UI Toolkit 的 `render_ui` 可以让我自检，这也是它唯一的效率优势。

## 七、3D 资产导入时机（玩家 / 敌人 / 场景模块）

### 7.1 原则

> **先管线，后资产；先一个，后一批；先灰盒验证，后批量替换。**

现在不要一次性把找到的模型全拖进 `Assets`。先导入 **1 个玩家 + 1 个杂兵 + 1 块地面**，跑通"导入 → 材质 → 动画 → 比例 → 性能"，再按批次推进。

### 7.2 导入批次

| 批次 | 时点 | 内容 | 目的 |
|---|---|---|---|
| **第 0 批（前置）** | 现在，半天 | 资产验收表、目录、导入 Preset、自定义 Shader、1 个测试模型 | 把管线跑通，避免后面批量返工 |
| **第 1 批** | W3 第 1~2 天 | 玩家模型 + 1 个近战杂兵 + 地面 tile | 验证比例、朝向、动画、材质；替换灰盒视觉 |
| **第 2 批** | W3 第 3~4 天 | 远程怪 + 自爆怪 + 树/石/边界 | 三种敌人剪影可区分；搭风格测试场 |
| **第 3 批** | W4 | Boss + 精英变体 + 装饰摆件/贴花 | Boss 战与氛围 |

### 7.3 第 0 批必须做的事

1. **资产验收表**：每个模型记录面数、贴图尺寸、骨骼数、动画 clip、朝向、单位、授权。
2. **目录**：按 `Assets/Art/Characters|Enemies|Environment|...` 落位，文件名遵循 `CH_/EN_/ENV_` 前缀。
3. **导入 Preset**：模型 Scale 1、Read/Write 关、Mesh Compression Off、生成 LOD、动画压缩开；贴图 sRGB/法线区分、Max Size 512/1024。
4. **自定义 Shader**：文档 2.3 约定的 `RuneAshes/Lit_Stylized` 目前工程里还没有。先写一个最小版本（BaseColor + Emission + Rim + HitFlash），否则导入的资产会积累一堆 URP Lit 材质，后面要批量换。
5. **一个测试模型**：只导入玩家，放进空场景，确认 1 unit = 1m、朝向 +Z、脚底在原点、动画能播。

### 7.4 逐项检查

| 项 | 要求 |
|---|---|
| 单位 | 1 Unity unit = 1m；玩家高 1.7~1.9m |
| 朝向 | +Z 为前；不一致的在导入设置里转，不要用代码补 |
| Pivot | 脚底中心；场景模块在底部中心 |
| 玩家骨骼 | ≤32 bones；6 clip（待机/移动/攻击/受击/冲刺/死亡）；根运动关闭 |
| 杂兵骨骼 | ≤16 bones 或 VAT；4 clip；采样 12~15fps |
| 面数 | 玩家 4k~8k；杂兵 800~2k；场景模块 200~1k |
| 贴图 | 512/1024；共享图集；不用 4K |
| 材质 | 统一换项目材质；不用资产自带材质 |
| 授权 | 每件登记来源与商用条款；AI 资产单独标注 |

### 7.5 三个高风险信号

1. **写实 PBR 资产**（4K 贴图、30+ bones、高面数）：不要用于 300 单位的杂兵。只能给 Boss/精英，或先减面/降贴图。
2. **骨骼过多的杂兵**：先评估能否降到 ≤16 bones；不能就只做精英，杂兵另找低模。
3. **场景模块拼接穿帮**：确认模块是 2m 网格、pivot 在底部中心、边缘可无缝拼接；否则先做一块 40×40 的测试场，不要直接搭关卡。

### 7.6 场景模块的导入节奏

- 先导入 **地面 4 种 + 边界 1 种 + 树 2 种 + 石 1 种**，搭一个 40×40 的"风格测试场"。
- 这个测试场只用于看风格与性能，不接玩法；W3 的竞技场仍用灰盒逻辑，只替换视觉。
- 装饰摆件（断碑/符文石/篝火）等到 W4，避免过早增加 Draw Call。

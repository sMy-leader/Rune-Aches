## 二、总表：哪些能后补，代价多大，现在必须做什么

## 三、热更（HybridCLR）：能补，但别在 W0 接

### 3.1 判断

- **技术上能后补**，代价 1~2 周（程序集拆分 + AOT 泛型 + 第三方包裁剪 + Unity 6.3 兼容验证）。
- **对 Steam 独游收益有限**：Steam 更新不走审核，代码热更主要省"玩家下载体积"和"紧急修 bug"，不是刚需。
- **真正的风险**：HybridCLR 对 Unity 6.3 的支持要现场验（Unity 6 支持较好，6.3 较新）；VContainer/UniTask 在热更程序集里的泛型与裁剪问题常在这时爆。
- **国内合规**：Steam 不涉及版号；若将来上 WeGame/TapTap，热更合规另说。

### 3.2 现在只做这三件事（半天成本）

1. **asmdef 分层**（依赖只能向下）：
   ```
   RuneAshes.Data      ← 生成的表 + ITableProvider（无依赖）
   RuneAshes.Framework ← 事件总线/对象池/随机/时间/资源接口（依赖 Data）
   RuneAshes.Gameplay  ← 符文/战斗/AI/玩家（依赖 Framework）
   RuneAshes.UI        ← 依赖 Gameplay
   RuneAshes.Editor    ← 单向依赖以上，**绝不反向**
   RuneAshes.HotUpdate ← 轨 B 才建，现在只留空目录
   ```
2. **Gameplay 里禁止出现**：`UnityEditor`、`AssetDatabase`、`Resources.Load` 直接调用、`switch(runeId)` 硬编码。
3. **写一页《AOT 约束清单》**：热更层禁用 `dynamic`、未标注的泛型实例化、`Marshal`、反射构造泛型；需要的泛型提前在 AOT 程序集里显式实例化一次。

### 3.3 面试话术（重要）

不要答"因为要上 Steam 所以热更"。正确答法：

> "架构上做了程序集分层和数据驱动，热更管线做了最小验证跑通；评估后认为 Steam 场景下代码热更收益低于维护成本，所以只保留配置热更（YooAsset + bytes），代码热更作为可选能力预留。"

这比"我接了 HybridCLR"更能体现判断力——面试官最怕的是"为了用而用"。

## 四、Luban：很容易补，前提是现在有"表访问层"

### 4.1 为什么容易

Luban 的本质是 **Excel → 生成的 POCO + 容器 + 数据文件 → 运行时读取**。业务代码只依赖"表对象"，不依赖生成器。所以：

- 现在：`Assets/Config/*.csv` + 一个 ~100 行的生成器 → `RuneTable.cs`（POCO + `TableBase<T>`）
- 将来：把生成器换成 Luban，`RuneTable` 由 Luban 生成，`ITableProvider` 实现换成 `Tables`
- **业务代码零改动**

### 4.2 现在定的接口（W0 就要有）

```csharp
// Data 层，无 UnityEngine 依赖
public interface ITableProvider {
    RuneTable   Runes   { get; }
    EnemyTable  Enemies { get; }
    WaveTable   Waves   { get; }
    void LoadAll();
    IReadOnlyList<string> Validate(); // 启动时跑：ID 唯一/引用完整/数值范围
}

public abstract class TableBase<T> where T : class {
    protected readonly Dictionary<string, T> _map = new();
    public T Get(string id) => _map.TryGetValue(id, out var v) ? v : throw new KeyNotFoundException(id);
    public IReadOnlyCollection<T> All => _map.Values;
}
```

**CSV 约定**：UTF-8 with BOM、首行字段名、`#` 开头为注释、列表用 `|` 分隔、枚举写字符串、空值有默认。
**启动校验**（比 Luban 更容易被忽略）：ID 重复、`next_id` 指向不存在、能耗/数值越界、图标文件缺失——全部报 console warning，不静默失败。

### 4.3 Luban 真正值得补的时点

- 表数量 > 8 张，或需要多人协作改表 → 值得
- 需要"配置热更 + 边玩边下" → 值得（Luban bytes + YooAsset）
- 切片期 3~5 张表 → CSV + 生成器完全够，**别提前支付**

## 五、存档：用 Newtonsoft；MessagePack 只留给分享码

### 5.1 先纠正原文档

原文写的是"局外 MessagePack、局内 run 用 Newtonsoft"，**正好反了**：

| 存档类型 | 频率 | 真正需要 | 选择 |
|---|---|---|---|
| 局外（图鉴/货币/槽位/设置） | 低 | **可读、可迁移、可回滚、玩家能发给我排查** | **JSON** |
| 局内 run 中断 | 极低（只在波次间隙存） | 快照完整性 | **JSON 足够** |
| 构筑分享码 | 高（每次导出） | **短** | **MessagePack + Base64Url** |
| 配置表 | 启动一次 | 只读、加载快 | CSV（将来 Luban bytes） |

### 5.2 为什么是 Newtonsoft 而不是 MessagePack（做存档）

1. **可调试**：玩家报 bug 时，一份明文 JSON 能直接看出"他卡在哪一关、买了什么"。二进制要写导入工具，solo 没这个预算。
2. **schema 演进**：加字段、改字段名、删字段，JSON + 默认值几乎零成本；MessagePack 要处理 `[Key]` 序号与旧档兼容。
3. **IL2CPP/AOT**：MessagePack 的泛型 resolver 在 IL2CPP 下常要额外配置；Newtonsoft 更成熟。
4. **数据量**：存档 < 100KB，JSON 的解析开销在加载界面完全不可见。
5. **依赖统一**：两套序列化 = 两套 bug。solo 项目减少依赖比"最优"更重要。

**安装**：`com.unity.nuget.newtonsoft-json`（Unity 官方维护包，不要自己塞 dll）。
**不要用** `JsonUtility`：不支持字典/多态/null，后期一定踩。

### 5.3 存档设计比库更重要（这些必须做）

```csharp
[Serializable]
public class SaveFile {
    public int version = 1;          // 第一位，永远
    public long savedAtUnix;
    public MetaSave meta;            // 图鉴/货币/槽位
    public SettingsSave settings;    // 音量/键位/画质/震屏
}
```

- **版本迁移链**：`Migrate(SaveFile v1) → v2 → v3`，每步一个纯函数，可单测。
- **原子写**：写 `.tmp` → `File.Replace(tmp, target, backup)`，防断电写坏。
- **双备份**：保留 `save.bak`，主档损坏自动回退。
- **校验**：文件尾加 SHA256 前 8 字节；不一致提示"存档损坏，使用备份"。
- **只存 ID 与数值**：绝不存 `GameObject`/`ScriptableObject` 引用/路径以外的场景信息。
- **加密**：单人游戏**不做**（防不住，还会让玩家没法备份）；最多做"校验和"。

### 5.4 分享码（轨 B，但数据结构现在就定）

```
[version:1B][charId:1B][slotCount:1B][ (runeId:1B, level:2b) × N ][checksum:2B]
→ MessagePack → Base64Url（去掉 + / =）
```
约 12~20 字节 → 16~28 字符。版本号必须在第一位，否则以后加符文就废了。

## 六、"接口先行"清单（W0 一次做完，后面所有替换都靠它）

| 接口 | 现在实现 | 将来替换 |
|---|---|---|
| `ITableProvider` | CSV + 生成器 | Luban |
| `IAssetLoader` | `Resources.Load` | YooAsset |
| `IRandom` | `Unity.Mathematics.Random`（**可播种**） | 种子系统/每日挑战/联机 |
| `ITime` | `Time.deltaTime` | 暂停/减速/顿帧统一入口 |
| `IInputSource` | Input System | 网络输入（NGO 预留） |
| `ISaveStore` | Newtonsoft + 文件 | 云存档/Steam Cloud |
| `IRuneEffect` | 原语实现 | 自由节点图（同一套原语） |

> 这 7 个接口是"后期任意换实现"的全部成本。少一个，后期就是全局搜索替换。

## 七、W0 落地清单（3 天，按顺序）

1. `git init` + `.gitignore`（Unity 模板）+ `.gitattributes`（LFS 追踪 `*.fbx/*.png/*.wav/*.psd`）
2. 工程改名（`RuneAshes` / 公司名占位），URP 设置：Linear、GRD、后处理 Volume、目标帧率
3. 建 5 个 asmdef（Data/Framework/Gameplay/UI/Editor），依赖单向
4. 输入 Action Map 重建：`Move`(WASD/左摇杆)、`Aim`(鼠标/右摇杆)、`Fire`、`Dash`、`Pause`
5. 7 个接口 + 空实现；`IRandom` 用可播种 RNG
6. CSV 生成器跑通 1 张 `rune.csv` → `RuneTable.cs`
7. Newtonsoft 安装 + `SaveFile` 读写 + 原子写 + 迁移链骨架
8. EditMode 测试 3 个：表校验通过、存档往返一致、RNG 同种子同序列
9. 一键构建脚本（菜单项 `Rune Ashes/Build Windows`）
10. 空场景出包成功

**验收**：空场景能出包、改 CSV 不出包即生效、存档写在 `%AppData%/../LocalLow/<company>/RuneAshes/`、同种子两次运行 RNG 序列一致。

## 八、资产导入后我做什么

你导入资产后，我用 MCP 跑一次自动化盘点（`execute_code` + `manage_asset`），输出：

- 模型清单：路径/面数/骨骼数/UV/是否有碰撞
- 贴图清单：尺寸/是否 sRGB/压缩格式/重复贴图
- 材质清单：数量/Shader/是否有实例克隆（合批风险）
- 命名与目录规范符合度
- 与《美术风格与资源清单_v1.md》P0 清单的缺口表

结果写成 `Docs/资产盘点报告.md`，直接决定"还缺什么、哪些能改色复用"。

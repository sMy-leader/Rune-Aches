## 零、先看结论

| 项目 | 结论 |
|---|---|
| **推荐风格** | **手绘低多边形（Stylized Hand-painted Low-Poly）+ 暗调环境 + 高饱和自发光符文** |
| 一句话美术方向 | "一座被余烬烧过的手绘低模世界：环境压在灰绿与焦褐里，只有法术和危险在发光。" |
| 次选 | PSX / PS1 复古低多边形（成本最低、辨识度高，但受众窄、弹幕可读性差） |
| 不推荐 | 写实暗黑 PBR（成本/一致性/性能三输）、纯赛璐璐卡通（要手绘贴图与描边，工作量反增）、2D 像素（与 3D 俯视定位冲突） |
| 核心手段 | 统一 LUT + 统一雾 + 统一色相规则 + 只有"伤害/可拾取"允许 Bloom |
| 资产来源配比 | 商店 50% / 自制&改色 30% / AI 生成 20%（AI 只做图标、贴图、摆件，不做角色绑定） |

**为什么是手绘低模**（四条硬理由，面试也能讲）：

1. **统一性可控**：低模 + 平涂 + 统一调色，是最能把"不同来源资产"拉到同一画面里的做法。写实 PBR 只要来源不同，粗糙度/法线/色温立刻穿帮。
2. **俯视可读性**：镜头在 8~12m 高、300 单位同屏、500 弹幕。写实细节在这个距离会糊成噪点；低模的大色块和清晰剪影才认得出"这是自爆怪"。
3. **性能**：单模型 1k~5k 三角面 + 512/1024 贴图，配合 SRP Batcher / GPU Instancing 才能撑住 300 敌人。写实资产直接吃掉预算。
4. **市场辨识度**：Steam 上幸存者类的成功作品（Vampire Survivors、Halls of Torment、DRG: Survivor）都是风格化。solo 用写实去打美术，是拿短板拼别人的长板。

## 一、视觉关键词与色彩脚本

### 1.1 视觉关键词（写进所有 prompt 与外包 brief）

```
hand-painted, low-poly, flat shading, clean silhouette,
muted desaturated environment, ember glow, ash particles,
dark fantasy, ruined sacred forest, rune-carved stone,
strong value contrast, readable at top-down 10m distance
```

禁用词：`photorealistic, hyperdetailed, PBR, 8k texture, film grain, lens flare, chromatic aberration`

### 1.2 色彩脚本（统一风格的第一手段）

| 层级 | 色相 | 饱和度 | 明度 | 备注 |
|---|---|---|---|---|
| 环境（地面/植被/建筑） | 灰绿 90~140° / 焦褐 20~35° | **20~35%** | 25~45% | 一律压暗压灰 |
| 玩家 | 暖白 / 浅金 40~50° | 15~25% | 75~90% | 全场最亮的中性色，加柔和轮廓光 |
| 敌人本体 | 暗红 0~15° / 暗紫 280~300° | 35~50% | 30~50% | 危险色，精英加发光描边 |
| **玩家弹幕** | 青 175~195° / 金 45° | 70~90% | 80~100% | 加 Bloom |
| **敌人弹幕** | 品红 320° / 橙红 10° | 80~100% | 70~90% | 必须与玩家弹幕**色相分离**，形状也要不同（圆 vs 菱形） |
| 可拾取物 / 符文 | 青绿 160~180° 自发光 | 70~90% | 80% | 加上升粒子 + 地面光斑 |
| UI 强调 | 琥珀 35° | 60% | 70% | 与场景暖光呼应 |

**可读性铁律（比风格更重要）**

1. 只有"会伤害你的"和"你能捡的"允许高饱和 + Bloom。环境一律去饱和。
2. 玩家弹幕与敌人弹幕**色相 + 形状双分离**，色盲玩家也能分。
3. 敌人剪影必须在纯黑剪影测试下可区分（近战/远程/自爆三种轮廓差异要大）。
4. 地面亮度永远低于角色亮度 ≥ 25%，否则俯视看不清。
5. 每个群系只允许一个"主色 + 一个点缀色"，不允许第三种高饱和。

### 1.3 三个群系的色彩分区（同一套资产语言，换色即换场景）

| 群系 | 主色 | 点缀 | 雾色 | 光源 | 情绪 |
|---|---|---|---|---|---|
| **腐化森林（切片期）** | 灰绿 + 焦褐 | 青绿余烬 | 青灰 | 冷月光 + 地面暖火光 | 压抑中的生机 |
| 废弃村庄（扩展期） | 土黄 + 暗橙 | 琥珀灯火 | 暖灰 | 黄昏斜阳 | 荒凉、有人住过 |
| 城市废墟（上架期） | 冷蓝 + 灰紫 | 紫罗兰符文 | 冷蓝 | 夜 + 局部烛火 | 宏大、终局 |

统一符号贯穿：**余烬粒子、发光符文刻痕、焦黑地面、漂浮灰烬**。换群系只换主色与道具，不换材质语言——这是"看起来是一个世界"的关键。

## 二、技术规格（由性能反推，不是拍脑袋）

### 2.1 性能预算（1080p 60fps / Steam Deck 800p 40fps 为目标）

| 项 | 预算 | 说明 |
|---|---|---|
| 同屏敌人 | 300 | 其中同屏**播动画**的 ≤ 60，其余降频/停播 |
| 同屏弹幕 | 500 | 用 GPU Instancing + 单材质 |
| 三角面总量 | ≤ 150 万 | 敌人占 ≤ 80 万 |
| Draw Call | ≤ 150 | 靠 SRP Batcher + Instancing + 图集 |
| 材质数量 | ≤ 25 | 每种敌人共享 1 材质，用 MPB 改色 |
| 实时阴影 | 只给玩家 + 精英 + Boss | 杂兵用贴地 blob shadow |
| 粒子 | ≤ 2000 活粒子，overdraw ≤ 屏幕 30% | 加法混合控制面积 |
| 贴图内存 | ≤ 400 MB | 1024 为主，共享 palette |

### 2.2 模型规格

| 类别 | 三角面 | 贴图 | 骨骼 | 动画 |
|---|---|---|---|---|
| 玩家 | 4k~8k | 1024（+ 3 套配色靠 MPB） | ≤ 32 bones | 待机/移动/攻击/受击/冲刺/死亡 6 clip |
| 杂兵 | 800~2k | 512（共享图集） | ≤ 16 bones 或**顶点动画/VAT** | 待机/移动/攻击/死亡 4 clip，12~15fps 采样 |
| 精英 | 3k~6k | 1024 | ≤ 24 bones | 6 clip + 词缀视觉变体（护盾/分裂/加速） |
| Boss | 15k~25k | 2048 | ≤ 48 bones | 8~12 clip，两阶段 |
| 场景模块 | 200~1k/件 | 512/1024 图集 | 无 | 无 |
| 植被 | 100~400/件 | 512 + Alpha | 无 | 风摆用顶点着色器，不做骨骼 |

**300 敌人动画的硬约束**：不要给 300 个杂兵全骨骼动画——CPU 蒙皮 + Animator 更新是第一个瓶颈。
做法（按优先级）：
1. **VAT / 顶点动画贴图**：同种敌人共享一张动画贴图，GPU 采样，零 CPU 蒙皮。
2. 简单骨骼（≤8 bones）+ **动画更新降频**（远距离每 2~4 帧更新一次）。
3. LOD：>20m 停止动画、>35m 切低模/billboard。
4. 材质共享 + `MaterialPropertyBlock` 做受击闪白/精英描边，避免材质实例爆炸。

> 这条必须写进美术 brief：**杂兵不要做精细绑定**，否则做完发现跑不动，返工代价极高。

### 2.3 材质与 Shader 约定（程序要按名字取参数）

统一使用一个自定义 `RuneAshes/Lit_Stylized`（基于 URP Lit 简化）：
- 参数：`_BaseMap` `_BaseColor` `_EmissionColor` `_EmissionStrength` `_RimColor` `_RimPower` `_HitFlash` `_DissolveAmount`
- 受击闪白走 `_HitFlash`（MPB），死亡溶解走 `_DissolveAmount`（MPB）
- 所有自发光统一走 `_EmissionColor`，后处理 Bloom 阈值 0.9，只吃自发光

**禁止**：每个敌人克隆材质（破坏合批）；用透明材质做不必要的东西（排序开销）。

### 2.4 动画技术约定

- 采样 12~15fps（风格化下更"手作"，也省内存）
- 所有 clip 必须 loop 无缝（待机/移动），攻击 clip 首尾对齐
- 根运动关闭（位移交给代码），攻击前摇/命中帧用 Animation Event 或配置表时间点
- 受击不做独立动画，用 `_HitFlash` + 位移抖动 + 顿帧

| 来源 | 占比 | 适合 | 风险 |

## 五、AI 生成 Prompt 模板

> 通用后缀（所有类别都加）：`stylized hand-painted, low-poly, flat shading, muted desaturated palette, dark fantasy, strong silhouette, game asset, centered, plain dark background, no text, no watermark`
> 通用负面：`photorealistic, hyperrealistic, pbr, 8k, lens flare, chromatic aberration, blurry, noisy, jpeg artifacts, text, logo, watermark, multiple views`（需要三视图时去掉 multiple views）

### 5.1 符文图标（最值得用 AI 的一类）

```
game icon of [概念], a glowing [青绿/琥珀] rune carved into dark stone,
[符号描述: an eye / a lightning bolt / an arrow splitting into three],
thick dark outline, high contrast, centered composition, 45 degree light,
transparent background, 256x256, --no text letters numbers
```
概念对照：T1 时钟 / T2 骷髅回响 / T3 连锁箭头 / T4 冲刺残影 / T5 破碎心脏 / T6 光环；E1 单箭 / E2 扇形三箭 / E3 环绕双球 / E4 地雷 / E5 刀锋冲刺 / E6 光束 / E7 哨戒图腾；M1 分裂三叉 / M2 弹射折射 / M3 穿透箭头 / M4 火焰 / M5 冰晶 / M6 爆炸 / M7 追踪之眼。

> 生成后必须人工做三件事：① 统一裁切与 padding ② 加同一套外发光 ③ 灰度剪影测试。

### 5.2 环境摆件 / 贴图

```
stylized hand-painted low-poly [ruined stone pillar / dead tree / iron fence],
dark fantasy corrupted forest, ash and moss, muted grey-green and charred brown,
game environment prop, 3/4 view, plain background
```

### 5.3 立绘 / 商店图（2D）

```
dark fantasy key art, a hooded rune-smith standing in a burned forest,
a chain of glowing cyan runes orbiting around them, embers floating,
muted desaturated background, strong rim light, cinematic composition,
negative space in upper third for logo
```

### 5.4 不要用 AI 做的事

- 3D 角色/敌人的**绑定与拓扑**（拓扑乱、UV 脏、骨骼不可用）
- 需要精确尺寸匹配的场景模块（拼接处会穿帮）
- 动画（AI 视频转骨骼质量不稳）

## 六、目录结构与命名规范

```
Assets/Art/
├── Characters/          CH_<Name>_<Variant>.fbx
├── Enemies/             EN_<Type>_<Name>.fbx
├── Environment/
│   ├── Ground/          ENV_Ground_<Name>_01.fbx
│   ├── Props/           ENV_<Type>_<Name>_01.fbx
│   └── Skybox/
├── VFX/                 VFX_<Event>_<Name>.prefab
├── UI/
│   ├── RuneIcons/       UI_RuneIcon_<ID>.png
│   ├── Icons/           UI_Icon_<Name>.png
│   └── Frames/
├── Materials/           MAT_<Category>_<Name>.mat
├── Textures/            T_<Category>_<Name>_<Size>.png
└── Animations/          AN_<Character>_<Action>.anim

Assets/Audio/
├── SFX/<Category>/      SFX_<Category>_<Name>_01.wav
└── Music/               BGM_<Scene>_<Mood>.ogg
```

规则：
1. 前缀决定类型，**文件名里的 ID 必须与 Luban/数据表一致**（`UI_RuneIcon_T2.png` ↔ `T2`）。
2. 变体用 `_A/_B/_C`，版本用 `_01/_02`，不用 `final`、`new`、`copy`。
3. 中文名一律不用（编码/跨平台问题）。
4. 导入后立刻套 `Preset`：模型（Scale 1、Read/Write 关、Mesh Compression Off、生成 LOD）、贴图（sRGB/法线区分、Mipmap、Max Size）。

## 七、验收清单（每批资产进来必须过）

**风格一致性**
- [ ] 灰度截图放在一起，明度关系是否统一（环境永远最暗）
- [ ] 所有资产是否同一套"平涂 + 硬边阴影"语言，没有混入写实法线细节
- [ ] 是否只有符文案/弹幕在发光

**可读性**
- [ ] 8m 俯视距离下，三种杂兵剪影可区分
- [ ] 玩家弹幕 / 敌人弹幕 色相 + 形状双分离
- [ ] 符文图标灰度后可区分
- [ ] 护盾/分裂/加速精英，1 秒内可识别词缀

**技术**
- [ ] 面数 / 贴图尺寸符合规格表
- [ ] 材质共享，无 per-instance 克隆
- [ ] 动画 loop 无缝，根运动关闭
- [ ] 无透明排序冲突、无缺失 UV、无 T-pose 残留
- [ ] 授权台账已登记

## 八、执行顺序（美术与代码并行）

| 周 | 美术动作 | 对应代码里程碑 |

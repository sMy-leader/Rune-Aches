## 一、为什么需要这份文档

数值表能回答"打多少"，回答不了"什么时候算打中、算谁的、能不能再触发"。
`击杀回响 + 分裂 + 爆炸` 这条链，如果不定规则，实现时会自然写成**事件递归**：
爆炸击杀 → 再触发击杀回响 → 再爆炸 → 一帧内上千次，直接卡死。
能耗是**静态**的，管不住**动态**递归。所以下面每一条都是工程约束，不是文案。

## 二、术语与数据模型

| 术语 | 定义 |
|---|---|
| **Cast（施法）** | 触发器满足条件后，整条链执行一次 |
| **Proc（触发）** | 触发器条件满足的那个事件 |
| **Hit（命中）** | 一次伤害判定成功 |
| **Chain（链）** | 1 触发器 + 1 效果 + N 修饰 |
| **ExecutionPlan** | 链编译后的不可变执行计划（struct 数组） |
| **castId** | 每次 Cast 自增分配，用于归属与去重 |
| **depth** | 本次 Cast 的递归深度；玩家直接触发 = 0 |

```csharp
struct DamageEvent {
    int    SourceChainId;
    int    CastId;
    byte   Depth;          // 0..MaxDepth
    float  Amount;
    DamageType Type;       // Direct / Dot / Explosion
    bool   IgnoreShield;   // 单发高伤破盾
}
```

## 三、归属规则

1. 一次 Cast 分配 `castId`，其产生的**所有**实体（弹丸、地雷、召唤物、DoT）继承 `castId / sourceChainId / depth`。
2. 击杀归属 = 造成最后一击的 `DamageEvent.SourceChainId`。
3. **召唤物击杀不触发主人的任何触发器**，只给经验与掉落。理由：否则 `E7 召唤物 + T2 击杀回响` 会无限召唤。召唤物自身的链（若将来有）独立结算。
4. DoT 的击杀归属给**施加 DoT 的那次 Cast**，不是刷新 DoT 的那次。

---

## 四、触发规则（防递归的核心）

| 规则 | 默认值 | 说明 |
|---|---|---|
| **禁止自激** | 开 | 同一次 Cast 产生的 Hit，不触发该 Cast 所属链的命中触发器。T3 不会因 E1 的命中而触发 E1 |
| **链内递归上限** | `depth <= 2` | depth 0 玩家直接触发；1 由链内击杀/命中再触发；2 为上限，超过丢弃 |
| **全局 Proc 预算** | 每 0.1s 最多 64 次 | 超出丢弃并计数 `ProcBudgetDropped`，用于性能与平衡观测 |
| **同帧合并** | 开 | 同一链同帧多次同类 Proc 合并为 1 次 Cast，伤害累加（不是 100 次 Cast） |
| **T3 命中传导 ICD** | 0.05s | 每 3 帧最多一次，防止散射/弹射把概率放大成必然 |
| **T5 受伤反击 ICD** | 1.0s | 与设计表一致 |
| **T4 冲刺余波** | 每次冲刺 1 次 | 冲刺结束事件只发一次，不按帧 |

> 这四条（自激、深度、预算、同帧合并）是"胡牌合法但不卡死"的全部保证。缺一条，Phase 1 就会踩。

## 五、修饰继承与叠加

1. **继承**：分裂/弹射/穿透产生的子弹继承当前链的全部修饰与 `depth`。
2. **分裂不可再分裂**：`splitDepth` 上限 1（分裂弹不能再分裂），但可以弹射/穿透。
3. **弹射次数是全局计数**：`bounces` 是整次 Cast 的预算，不是每颗子弹各 2 次。
4. **伤害乘区**：修饰按乘法叠加；单个修饰乘区下限 0.3；单次 Cast 总乘区上限 20×（防爆表）。
5. **同名修饰**：默认同一条链最多 1 个（装配时直接禁止，并提示"已装备"）。
   - 备选：允许第 2 个但效率 50%（递减叠加），保留构筑自由度。见第 12 节决策 4。
6. **DoT**：同源刷新持续时间不叠层；不同源可叠层，上限 3 层。
7. **冰冻**：叠 3 层触发冻结 1s；冻结期间不再叠层，冻结结束后层数清零。
8. **燃烧**：刷新，不叠层。

## 七、护盾 / 无敌 / DoT 交互

1. **护盾**：吸收固定值；`单次伤害 > 阈值` 时无视护盾（破盾），破盾后 3s 内受伤 +20%。
   —— 这是对原设计"每次受伤上限 5"的修正：原规则会直接杀死高频流，不是"考题"而是"禁用"。
2. **DoT**：不被"单次伤害上限"限制，但被护盾吸收；**DoT 不触发命中**（否则燃烧自己滚雪球）。
3. **玩家无敌帧**：免疫直接伤害与爆炸；**已在身上的 DoT 继续跳**；无敌不阻止击退。
4. **敌人硬直**：受击不打断攻击前摇（防无限控）；只有冻结能打断前摇。

## 八、死亡结算顺序（必须严格按序）

```
1. 扣血
2. 标记 dead（此后不再受击、不进目标列表）
3. 触发 OnKill（带 sourceChainId / depth）
4. 执行击杀类修饰（爆炸 / 分裂）
5. 掉落经验 / 符文币
6. 从空间哈希移除
7. 回对象池（Reset 契约）
```

关键：**先标记 dead 再触发爆炸**。否则同一具尸体会被自己的爆炸再炸一次，产生双倍掉落与双重击杀事件。

## 九、链编译（ChainCompiler）

```
ChainBlueprint (数据: triggerId, effectId, modifierIds[], levels[])
        │
        ▼ 编译（改链时一次，不是每帧）
ExecutionPlan (不可变 struct 数组 + 预分配缓冲)
        │
        ▼ 运行时只跑 plan，不遍历 SO
```

编译期校验（装配 UI 必须给"移除哪个才能装上"的具体建议）：

- 恰好 1 个触发器、1 个效果
- 槽位数 ≤ 当前上限
- 总能耗 ≤ 上限
- 同名修饰 ≤ 1（若采纳默认）
- 所有 ID 存在于 `RuneTable`

## 十、确定性随机

1. 所有玩法随机走 `IRandom`，禁止 `UnityEngine.Random`。
2. 每次 Cast 的 RNG 由 `Hash(runSeed, castId, salt)` 派生独立实例，避免"触发顺序影响掉落"。
3. 三选一、掉落、词缀、波次全部由 `runSeed` 派生；同种子 = 同结果。
4. 这样种子系统 / 每日挑战 / 回放 / 联机都不需要返工。

## 十一、性能约束（写进代码评审清单）

- 每次 Cast **零托管分配**：ExecutionPlan 预分配，弹丸池化，事件用 struct。
- 弹丸层与敌人层各一张空间哈希；受击只标记，不清空整表。
- 同帧合并 + Proc 预算，保证最坏情况可控。
- 所有 `List<T>` 用容量预分配；禁止在 Update 里 `new`。

## 十二、已确认的 5 个决策（2026-10-28）

| # | 决策 | 结论 | 备注 |
|---|---|---|---|
| 1 | 链内递归深度上限 | **depth ≤ 2** | 能链式殉爆但可控；超过丢弃 |

| 5 | 切片期槽位 | **4 槽**（触发+效果+2 修饰） | demo 能演示两次"加修饰→质变" |
